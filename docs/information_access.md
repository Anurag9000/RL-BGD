# Information Access

Information access is treated as part of the experimental method, not as an
informal benchmark note.

## Strict task-agnostic contract

A strict learner may receive ordinary interaction information generated by its
own trajectory:

- observation;
- action;
- reward;
- terminated/truncated signal;
- replay metadata such as transition age/use count;
- its own recurrent hidden state and previous-transition context.

It may not receive:

- ground-truth task ID or task name;
- task-boundary/switch callbacks;
- simulator context parameters;
- evaluator-only change times;
- task-routed heads, buffers, or resets unless the protocol explicitly permits
  them.

`InformationAccessConfig.validate_strict_task_agnostic()` is the central
executable guard. Benchmark adapters additionally strip task/context fields and
have leakage tests.

## Privileged comparison protocols

Not every baseline is task-agnostic. Canonical Continual World deliberately
uses task identity/multi-head routing to match the published protocol.
Oracle-boundary UCL and boundary-triggered regularization variants snapshot or
consolidate at known boundaries. These runs are valid comparators only when
their privileged access is recorded; they are never relabelled strict
task-agnostic.

## Recurrent context

Recurrence is not treated as task-ID access. A recurrent agent can infer latent
context from the history of observations/actions/rewards/done flags, but hidden
task switches do not reset its state. Episode termination/truncation may reset
state because it is ordinary environment information.

## Evaluator separation

Evaluation code may know task names, task indices, true environment change
times, or the set of task-specific evaluation environments. That information is
used to compute performance matrices/change-detection metrics and must not flow
back into training.

## Artifact provenance

Every canonical run manifest stores a normalized
`information_access` mapping. The Phase-15 paper builder verifies that all
matched seeds in an experiment group have identical access assumptions and
exports an automatic information-access table. Runner-emitted access metadata
may add detail, but it may not contradict protocol invariants inferred by the
suite registry.

This separation is essential when comparing boundary-free Bayesian
replasticization, recurrent context inference, canonical task-aware protocols,
and oracle-boundary baselines.
